# 构建与发布

代码仓库为 [cyberspacesec/gxx](https://github.com/cyberspacesec/gxx)，默认分支为 `main`。根模块路径为 `github.com/cyberspacesec/gxx`，最低 Go 版本为 **1.25.0**。

## SDK 安装

在调用方的 Go 模块中执行：

```bash
go get github.com/cyberspacesec/gxx/sdk@v1.1.9
```

导入 `github.com/cyberspacesec/gxx/sdk`，调试接口导入 `github.com/cyberspacesec/gxx/sdk/debug`。调用方无需本地 `replace`。CLI 源码入口为 `github.com/cyberspacesec/gxx/cmd`。

IDE 是 `cmd/gxx-ide` 下的独立模块，其本地 `replace github.com/cyberspacesec/gxx => ../..` 用于在同一 checkout 中构建当前引擎；根 SDK 模块不包含本地替换。

## 持续集成

推送 `main`、提交面向 `main` 的 Pull Request 或手动执行“持续集成”会检查：

- 根模块的静态检查、完整测试、竞态测试和内置指纹构建测试。
- IDE 后端的静态检查与竞态测试。
- IDE 前端的锁定依赖安装、测试、类型检查和构建。
- Go 模块文件与前端依赖锁文件未被构建过程改变。

流水线固定使用 Go **1.25.0**，设置 `GOTOOLCHAIN=local` 与 `-mod=readonly`。IDE 使用 Node.js 24，Wails CLI 版本读取 IDE 的 `go.mod`，当前为 `v2.12.0`。

## 发布流程

版本标签使用 `v` 前缀和语义版本，如 `v1.1.9`。版本标签必须指向 `main` 的提交。按 [Go 模块发布规范](https://go.dev/doc/modules/publishing)，已发布的版本标签不得移动或覆盖。

“构建与发布”可以手动执行，使用 `wails.json` 的产品版本生成完整测试产物，不发布 Release。核对构建后推送标签：

```bash
git push origin main
git tag -a v1.1.9 -m "GXX 1.1.9"
git push origin v1.1.9
```

标签触发完整持续集成检查，检查通过后生成九个 ZIP：

| 产品 | 平台与架构 |
| --- | --- |
| GXX CLI | macOS amd64、arm64；Linux amd64、arm64；Windows amd64、arm64 |
| GXX IDE | macOS amd64、arm64；Windows amd64 |

CLI 使用内置指纹库，产物名称保持 `gxx_{平台}_{架构}_{版本}.zip`，流水线跳过 UPX 压缩，避免启动时解压带来的时间和内存开销。IDE 为 `gxx-ide_{平台}_{架构}_{版本}.zip`，macOS 使用原生架构 Runner，Windows 使用原生 Windows Runner。IDE 产物未经开发者证书签名或公证。

所有平台构建成功且 ZIP 内容核对通过后，流水线生成 `SHA256SUMS`，在独立 Go 模块中通过 `go get` 安装标签版本并执行本机 SDK 扫描，随后向 GitHub Release 草稿上传完整资源，再公开发布。仅发布任务拥有 `contents: write` 权限，其他任务只读。第三方 Actions 固定到已核对的提交 SHA，依据 [GitHub Actions 文档](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax) 配置。

## Git 元数据与配置

`.git` 是本地 Git 元数据，不参与源码跟踪或发布包；忽略规则同时覆盖目录与 worktree 的 `.git` 文件。`.gitlab/` 和 `.gitlab-ci*.yml`、`.gitlab-ci*.yaml` 保留为本地忽略文件，仓库的持续集成入口为 `.github/workflows/`。忽略规则不会自动取消已有跟踪，迁移时需要停止跟踪 GitLab 配置。

发布 ZIP 只收集指定二进制或应用目录，发布前检查路径及内容，拒绝 Git 元数据、GitLab 配置和越界路径。
