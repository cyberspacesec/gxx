# 网络策略

网络策略约束引擎发出的**全部**出站连接：入口与跳转、HTTP 规则、Raw HTTP、TCP、UDP、页面图标、附属资源（robots.txt、sitemap.xml、标题脚本）、TLS 探测（JARM）以及代理健康探测。没有设置策略时，引擎的行为与之前的版本相同。

```go
type NetworkPolicy struct {
    Dial          func(ctx context.Context, network, address string) (net.Conn, error)
    CheckTarget   func(ctx context.Context, request TargetRequest) error
    Redirect      func(ctx context.Context, from, to *url.URL) RedirectAction
    WrapTransport func(base http.RoundTripper) http.RoundTripper
}
```

四个字段相互独立，未设置的字段保持默认行为。

## 设置方式

| 入口 | 作用范围 |
|---|---|
| `sdk.WithNetworkPolicy(policy)` | 引擎级：该引擎的全部扫描、`GetBaseInfo`、`WappalyzerScan`、`NormalizeURL` |
| `engine.ScanWith(ctx, target, sdk.ScanNetworkPolicy(policy))` | 扫描级：只作用于这一次扫描（`DebugRule` 同样接受） |

扫描级策略**逐字段覆盖**引擎级策略：扫描级中非 nil 的字段替换引擎级的同名字段，nil 字段沿用引擎级。例如引擎级设置了 `CheckTarget`，扫描级只设置 `Redirect`，这次扫描两者都生效。

扫描级策略经 context 传到已缓存的 Transport，不为每次扫描新建 Transport。扫描级设置了 `Dial` 时，这次扫描的 HTTP 请求使用一个不复用连接的 Transport（按代理缓存一份、所有此类扫描共用），每个请求各自拨号，连接用完即关闭：一次扫描拨出的连接不会被其他扫描取用，不同扫描的 `Dial` 互不混用。引擎级的 `Dial` 对所有扫描相同，连接照常复用。

## Dial

`Dial` 替代直连拨号。未配置代理时用它连接目标；配置了代理时用它连接**代理服务器本身**（HTTP CONNECT、SOCKS4/5、SOCKS5 UDP 的控制连接与中继），代理健康探测同样经过它。`Dial` 收到的 ctx 只约束建立连接的过程，连接建立后的读写由引擎按超时管理。

HTTPS 连接先由 `Dial` 建立 TCP 连接，再由引擎完成 TLS 握手（握手期间记录 TLS 信息，见 [TLS 信息与指纹](TLS信息与指纹.md)）。

## CheckTarget

`CheckTarget` 在**每次**发往目标之前调用：HTTP 请求的每一跳与每次重试、宽松回退、Raw HTTP 的每一跳、TCP/UDP 规则的每次连接与重连、图标与附属资源请求、JARM 的每个探测、代理健康探测中经代理访问的目标。经代理隧道访问的目标同样检查，检查发生在连接代理之前。

返回错误即拒绝：引擎不会向该目标发出任何字节（经代理时也不会请求代理建立隧道），请求返回 `*sdk.DeniedError`（即 `*network.DeniedError`），不重试。被拒绝的规则请求按请求失败处理，规则视为未命中；求值报告中记为 `request`。

```go
type TargetRequest struct {
    Kind     RequestKind // http raw tcp udp icon resource tls
    Network  string      // tcp / udp
    Host     string      // 未解析的主机名或字面 IP
    Port     string      // 省略的端口按协议补全
    URL      *url.URL    // HTTP、Raw、图标、附属资源时非空
    RuleID   string      // 规则请求时为规则标识
    Redirect bool        // 是否为跳转产生的下一跳
}
```

`Kind` 的含义：

| Kind | 连接 |
|---|---|
| `http` | 入口、入口跳转链、HTTP 规则请求、反连平台查询 |
| `raw` | Raw HTTP 规则请求（含其跳转） |
| `tcp` / `udp` | TCP / UDP 规则；未标注用途的 `network.DialContext` 按网络类型 |
| `icon` | 页面图标 |
| `resource` | robots.txt、sitemap.xml、标题 i18n 脚本 |
| `tls` | JARM 探测 |

`Host` 是**未解析**的主机名或字面 IP。需要按解析后的地址判断（例如禁止访问内网地址）时，在 `Dial` 中解析并检查：`Dial` 收到的地址就是即将连接的地址。经 `socks5` / `socks5h` 代理时，域名以原样发给代理，由代理解析，本端无法检查解析后的地址。

## Redirect

`Redirect` 决定引擎**本来会跟随**的跳转是否跟随：入口跳转链上的 30x、刷新与脚本跳转，HTTP 规则与 Raw HTTP 的 30x，图标与附属资源的 30x。返回 `RedirectStop` 时不访问下一跳：

- 入口跳转链：保留已取得的页面，下一跳的地址写入 `RedirectTo`，`Redirects` 中这一跳的 `Followed` 为 `false`，不作为错误；
- 规则请求、图标与附属资源：返回发出跳转的 30x 响应本身。

`Redirect` 只能阻止跟随。引擎本来不会访问的跳转（例如指向其他资产的刷新与脚本跳转，见 [资产与跳转](资产与跳转.md)）不会因为返回 `RedirectFollow` 而被访问。为 nil 时保持默认的跟随规则。

## WrapTransport

`WrapTransport` 包装 HTTP 请求的底层 `http.RoundTripper`，图标与附属资源请求同样经过它；Raw HTTP、TCP、UDP 与 TLS 探测不经过 RoundTripper。引擎级的包装在创建客户端时执行一次；扫描级的包装在该次扫描中对每个底层 Transport 执行一次。目标检查、限速与 Cookie 会话在包装之外进行，包装函数看到的是即将发出的请求。

## 示例

```go
// 禁止访问内网：Dial 中按解析后的地址判断，CheckTarget 拦截字面 IP 与指定主机。
private := func(ip net.IP) bool { return ip.IsPrivate() || ip.IsLoopback() || ip.IsLinkLocalUnicast() }
policy := sdk.NetworkPolicy{
    Dial: func(ctx context.Context, network, address string) (net.Conn, error) {
        host, port, err := net.SplitHostPort(address)
        if err != nil {
            return nil, err
        }
        ips, err := net.DefaultResolver.LookupIP(ctx, "ip", host)
        if err != nil {
            return nil, err
        }
        for _, ip := range ips {
            if private(ip) {
                return nil, fmt.Errorf("拒绝连接内网地址 %s", ip)
            }
        }
        return (&net.Dialer{}).DialContext(ctx, network, net.JoinHostPort(ips[0].String(), port))
    },
    CheckTarget: func(ctx context.Context, request sdk.TargetRequest) error {
        if ip := net.ParseIP(request.Host); ip != nil && private(ip) {
            return errors.New("拒绝内网地址")
        }
        return nil
    },
}
engine, err := sdk.NewEngine(ctx, sdk.WithNetworkPolicy(policy))

// 某次扫描不跟随离开扫描目标的 30x。
result, err := engine.ScanWith(ctx, target, sdk.ScanNetworkPolicy(sdk.NetworkPolicy{
    Redirect: func(_ context.Context, from, to *url.URL) sdk.RedirectAction {
        if from.Host != to.Host {
            return sdk.RedirectStop
        }
        return sdk.RedirectFollow
    },
}))
```

`pkg/network` 的使用方可以用 `HTTPClient.SetPolicy` 设置客户端级策略、`HTTPClient.WithPolicy(ctx, override)` 设置请求级覆盖；`network.DialContext`、`network.NewClientContext` 与 `network.CheckProxy` 读取 ctx 中的策略。

## 验证

`sdk/egress_test.go` 的出站覆盖矩阵对 HTTP、HTTPS、HTTP CONNECT 代理、SOCKS5、SOCKS5 UDP、Raw HTTP、TCP 规则、UDP 规则、同源与跨源图标、30x 跨主机、刷新与脚本跳转、重试、代理健康探测、附属资源与 JARM 分别在允许与拒绝下执行，拒绝时用本机监听的计数断言没有任何连接或字节到达目标。`pkg/network/policy_test.go` 覆盖逐字段覆盖、扫描级 `Dial` 的连接不复用与 `Redirect`。
