# 资源读取与实例隔离

## 读取范围与内存

当前 HTTP 页面正文读取上限为 512 KiB，包括基础响应、普通规则、Raw HTTP 和标题脚本获取。256 KiB 是性能测试负载的大小，不是项目默认上限。超出正文范围的规则关键字、页尾备案号、图标声明和内联图片可能无法识别；提高限制能扩大读取范围，也会增加最坏情况的内存与传输时间。

图标作为独立资源处理：有效 HTTP 图片读取到真实 EOF，哈希计算使用固定大小的原始块和编码块，不保留完整图片或完整 Base64 副本。大小没有上限，扫描超时和 context 取消仍然生效。提前断流、错误的 Content-Length、超时和取消不能产生前缀哈希。明确的 HTML 错误页提前停止读取；长 XML 前导不能使 SVG 被当作错误页。

内联图片按完整的 Data URI 声明解码；解码器不建立完整解码副本。页面正文在声明结束前被截断时，该声明不参与计算。字节哈希采用 MurmurHash3 32 位、原有 Base64 行宽、补齐和最终换行约定；同一组原始字节的哈希不变。内联输入取实际图片字节，与 HTTP 获取同一图片的结果一致。

响应缓存完整保存已读取的消息，不再对正文、Raw 或字段分别裁剪。内部消息按只读所有权共享；公共写入复制调用方消息。完整消息超过缓存字节预算时直接跳过，公共写入在复制前检查容量。缓存预算、正文上限和进程内存分别是三个概念，64 MiB 缓存预算不是 RSS 上限。

通用 CEL 规则可以访问完整正文及 Raw 响应，当前消息结构通常持有二者的独立字节数组。正文大小乘以并行在途响应数，加上解析、字符集转换、结果保留及缓存，才接近实际内存需求。正文处理不能像图标哈希一样，仅靠固定块就保持全部 CEL 语义。

## 正文策略选择

正文默认值保持 512 KiB，以下选项需要确认后落地；所有选项都保持独立 HTTP 图标完整读取。

| 方案 | 读取策略 | 资源与覆盖范围 |
|---|---|---|
| 4 MiB | 默认 4 MiB，允许实例覆盖 | 建议的资源与覆盖范围折中；页尾内容更可能被读取，超过 4 MiB 仍可能漏报 |
| 10 MiB | 默认 10 MiB，允许实例覆盖 | 对齐 Nuclei Go SDK 当前默认；大响应并发时内存和传输开销更高 |
| 不限量 | 正文读取到 EOF，保留超时与取消 | 读取完整正文；单个超大响应的内存无法用缓存预算约束，需要额外设计在途字节预算、排队或磁盘处理策略 |

确认后，读取策略需要在基础信息、普通规则、Raw HTTP、标题脚本与 IDE 调试入口统一传递，不能仅修改一个常量。截断状态应可观测，缓存保持完整存储或跳过的约定。不限量不能同时承诺任意 CEL 规则语义、任意大响应和固定进程内存上限。

## SDK 实例归属

SDK 使用 `NewEngine(ctx, options...)`、带 context 的扫描入口、`Close()` 生命周期和函数式选项。实例持有扫描业务状态，配置在构造期复制；该调用方式与 [Nuclei Go SDK 的官方入口](https://github.com/projectdiscovery/nuclei/blob/dev/lib/README.md)相符。本项目不直接依赖或嵌入 Nuclei 引擎。

| 状态 | 归属与约束 |
|---|---|
| 请求头、代理、超时、TLS、Keep-Alive | 当前 Engine / HTTP 客户端；请求头构造时复制 |
| CookieJar、连接池、限流器 | 当前 HTTP 客户端 / Engine |
| 图标成功哈希 | 当前 HTTP 客户端，按需分配的 4,096 项 LRU；键为资源和请求上下文摘要，关闭实例释放 |
| 反连平台配置 | `WithReverseConfig` 按值传递至规则执行者，查询使用所属实例客户端 |
| YAML 规则解析顺序 | 当前解析调用，无包级计数器与解析锁 |
| 请求缓存 | 当前 Engine 的容量预算，单次 Scan 的作用域隔离 |
| 规则执行变量、取消、输出队列 | 当前扫描 / Engine；归还求值对象时清除扫描引用 |
| CEL 程序、技术栈索引 | 可共享的编译程序和只读索引，不包含实例认证信息或扫描变量 |
| 对象池 | 进程内可复用；一次只由一个执行者借用对象 |
| Go GC、堆与 runtime 内存统计 | 整个进程，所有 Engine 合计 |
| 自定义 Writer、Logger、相同输出路径 | 调用方显式共享时由调用方管理；内部隔离不会复制外部资源 |

第一实例未完成时创建、取消或关闭第二实例，不应覆盖第一实例的配置。未注入客户端的独立 `finger` 辅助调用可以使用进程默认 HTTP 客户端；SDK 扫描链路传递所属实例的客户端。不同操作系统进程的 Go 变量与堆独立，文件、Socket 和外部服务仍可能显式共享。

## 代码边界

`sdk/` 提供公开入口，`pkg/runner/` 管理生命周期与调度，`pkg/network/` 管理请求和资源缓存，`pkg/finger/` 管理规则与网站元数据，`internal/` 保存不对外暴露的内部组件，`cmd/` 保存 CLI / IDE。这一职责划分可以保留，移动目录本身不会降低运行时内存。

旧的包级反连配置、进程图标缓存入口、无 context 的网络构造及发送包装、空 Raw HTTP 接收器、旧字符串响应构造、重复技术栈入口、全局解析计数器和无调用路径的工具函数不属于当前 SDK 入口。没有实际读取路径的 HTTP `Retries` 字段不作为有效配置暴露，TCP / UDP 的 `MaxRetries` 保持有效。原始报文编解码只引用所需的子包，不导入无调用路径的进程默认 Raw HTTP 客户端。清理范围不包含当前仍有业务意义的 SDK 配置和诊断 API；调用树工具找不到外部使用方，不能据此判定公开入口是死代码。

两个模块的最低 Go 版本均为 1.25.0，验证显式使用该工具链，依赖以各自的 `go.mod` 与 `go.sum` 为准。

## 验证与测量记录

2026-09-30（GitHub 模块迁移前），macOS / Apple M2，使用 Go 1.25.0，该轮验证中两个模块的 `go.mod` / `go.sum` 均未变动。根模块与 IDE 的全量测试、race 和 vet 通过，CLI 普通构建、嵌入规则构建及 IDE 构建通过。实例重叠与 Raw HTTP 取消分别在 race 模式重复验证 20 次。ICP 模糊测试完成 613,239 次输入验证，内联图片哈希模糊测试完成 10,556 次；这是有限测试覆盖，不能证明所有网站都等价。

以当日保存的响应处理实现为基线，使用全部 2,348 条指纹、200 个规则工作协程及固定 Apache / WordPress 阳性响应，交替测量 3 组。小响应和请求头场景每组扫描 100 次，大响应及 Unicode 场景 40 次，复杂 HTML 20 次；5 目标并发分别扫描 100 次和 80 次。以下为组均值的中位数，箭头表示基线到当前实现。

| 负载 | 每目标累计分配（MiB） | 每目标耗时（ms） | 进程峰值 RSS（MiB） |
|---|---:|---:|---:|
| 小响应 | 0.937 → 0.889 | 4.330 → 3.229 | 85.08 → 74.33 |
| 256 KiB 分块响应 | 15.834 → 12.748 | 28.647 → 28.093 | 108.05 → 97.23 |
| 256 KiB 已知长度响应 | 15.890 → 12.780 | 30.027 → 31.534 | 107.81 → 95.14 |
| 5 目标并发、小响应 | 0.941 → 0.900 | 4.073 → 2.093 | 93.16 → 79.98 |
| 5 目标并发、256 KiB 响应 | 15.995 → 12.822 | 11.833 → 10.480 | 157.25 → 136.66 |
| Unicode 响应 | 0.960 → 0.914 | 5.833 → 4.080 | 80.36 → 68.17 |
| 复杂 HTML | 30.347 → 24.395 | 107.380 → 80.965 | 115.61 → 103.95 |
| 16 个自定义请求头 | 1.158 → 1.199 | 4.624 → 3.106 | 85.77 → 73.91 |

八类完整 SDK 输出对照一致。静态标题、DOM 标题、i18n 与 GB18030 四种整库回放的 SDK 输出也一致，共完成 9,392 次规则任务。实际 HTTP 请求为 45 → 53 次，差异全部是各页面的图标请求 2 → 4 次：带不同请求头 / Cookie 的规则不再错误复用另一请求上下文的成功哈希，其他请求计数相同。

已知长度负载耗时增加约 5%，请求头负载累计分配增加约 3.5%；其他有限负载不能抵消这些回退，也不能据此宣称所有场景性能最优。RSS 包含冷启动，累计分配包含同进程本机靶场；这些指标与扫描后的存活堆、HTTP 流量和实际网络吞吐不同。实际部署仍需结合目标延迟和响应大小调整并发。

元数据提取另外交替测量 5 组：无备案号中文 HTML 为 220.5 → 106.2 μs，均为零分配；256 KiB 正文末尾的备案号为 13.10 ms → 67.9 μs；256 KiB 页面的图标地址提取为 314.3 → 5.0 μs。实体号码在基线中未识别，当前能识别，因此其耗时不能作为相同工作量的速度对照。

独立完整图标基准测量 3 组。输入数据预先存在，数字包含 Reader、哈希状态和暂存区的累计分配，不包含输入图片、HTTP / TLS 缓冲和服务端内存。

| 完整图标大小 | 固定块读取分配 | 先 `ReadAll` 再计算分配 | 固定块读取耗时 | 先读入内存耗时 |

| 4 MiB | 4.75 KiB | 20.13 MiB | 4.74 ms | 5.97 ms |

带 SVG 内容识别时分配仍为 4.75 KiB。图标没有被截断，哈希额外分配不随图片大小增长；正文读取及通用规则求值没有这个固定内存保证。
