# 资产与跳转

GXX 以**资产**为单位识别。本文说明资产的边界、扫描过程中哪些跳转会被跟随，以及结果里与跳转有关的字段。

## 资产

一个资产由**协议、主机、端口**共同确定：

| 输入 | 资产 |
|---|---|
| `http://a.com` | `http://a.com:80` |
| `https://a.com` | `https://a.com:443`，与上一行是两个资产 |
| `http://a.com:8080` | 第三个资产 |
| `http://www.a.com` | 第四个资产 |

主机不区分大小写，省略的端口按协议补全，所以 `http://A.com:80/` 与 `http://a.com` 是同一个资产。

目标未写协议时由 GXX 确定：端口 80 只尝试 http，端口 443 只尝试 https，其余先 https 后 http。写成 `ip:端口` 时两种协议连接的是同一个端口，TCP 连接失败就不再换协议，不可达的目标只等待一次超时。

## 请求不离开资产

扫描一个资产时，入口请求和所有规则请求都只发往这个资产。30x 指向其他资产（协议、主机或端口不同）时**停在 30x 响应**：

- 不向对方发出任何请求，自定义请求头不可能泄漏到其他主机。
- 结果描述的是 30x 响应本身（状态码、响应头、Server），对方页面的标题和指纹不会记到本资产名下。
- 对方的地址写入结果的 `redirect_to`，由调用方决定是否把它作为新的目标扫描。

例如 `http://a.com` 把所有请求 301 到 `https://a.com`：扫描 `http://a.com` 得到状态码 301 和 `redirect_to: https://a.com/`；要识别 https 上的站点，把 `https://a.com` 作为目标。

唯一会访问资产以外主机的是**页面明确声明的图标**（`<link rel="icon">` 等，常托管在 CDN）。图标请求按浏览器的方式跟随重定向，最多 5 跳，离开原主机后不携带自定义请求头。没有声明图标时猜测的候选（`og:image`、`<img>`、图片链接）只在本资产内请求。30x 响应不提取图标。

## 资产内的跳转链

入口请求在资产内逐跳跟随，合计最多 5 跳，回到已访问过的地址时停止。会被跟随的跳转：

| 类型 | 说明 |
|---|---|
| `http` | 30x 的 `Location` |
| `refresh` | `Refresh` 响应头或 `<meta http-equiv="refresh">`，延迟不超过 10 秒且带有地址；`<noscript>` 中的不算 |
| `javascript` | 跳转壳里的脚本跳转，见下 |

链上的**每一页都是指纹素材**：

- 规则里的 `path: /`（跟随重定向的 GET）依次匹配链上各页，任一页满足即命中。入口的 302 响应本身（状态码、`Location`、`Set-Cookie`）和最终页面的内容都可以写规则。
- 一条指纹的多条规则要在**同一页**上成立；分别落在不同页面上的规则不会拼成一次命中。
- `follow_redirects: false` 的根路径规则只匹配第一页，并复用入口响应，不再另发请求。
- 其他路径的规则（如 `path: /admin`）仍以扫描目标为前缀单独请求，同样只在资产内跟随 30x。

结果中的标题、技术栈、备案号、图标哈希和 `status_code` 取自链上最后一页。

### 脚本跳转的识别范围

GXX 不执行 JavaScript，只做静态识别，并且只识别写法明确的情况；识别不了就当作没有跳转。

页面必须是**跳转壳**：正文不超过 16 KiB，没有表单、输入控件和框架，可见文字不超过 512 字节。在这样的页面里查找：

- `location`、`location.href` 的赋值，以及 `location.replace()`、`location.assign()` 调用；`location` 可以挂在 `window`、`self`、`top`、`parent`、`document`、`globalThis` 上，其他对象的同名属性不算。
- 目标必须是字符串字面量。字面量后用 `+` 拼接时，只有字面量已经包含 `?` 才采用——路径是完整的，拼接的是时间戳一类的参数值，例如 `"/doc/page/login.asp?_" + (new Date()).getTime()`。
- 整个页面只出现**一个**不同的目标才跟随。按设备或语言分流的多目标写法无法静态判断，放弃。

字符串和注释里的"代码"、比较（`==`）、追加（`+=`）、`location.hash`、`window.open`、外链脚本、模板插值都不会被当成跳转。

识别到的地址如果属于其他资产，同样不访问，只写入 `redirect_to`。因此识别出错的最坏结果是多请求一次本资产的另一个页面，而且入口页仍然参与匹配，不会把别的资产当成本资产。

## 结果字段

| 字段 | 含义 |
|---|---|
| `url` | 资产入口，即带协议的扫描目标 |
| `final_url` | 资产内最后一页的地址；没有跳转时与 `url` 相同 |
| `redirect_to` | 指向其他资产、没有跟随的跳转地址；没有则省略 |
| `redirects` | 跳转链，每一跳包含 `type`、`status`（发出跳转的响应的状态码）、`from`、`to`、`followed` |
| `status_code`、`title`、`tech_stack`、`icp`、`headers` | 描述 `final_url` 对应的页面 |

`followed` 为 `false` 的一跳就是 `redirect_to` 的来源。SDK 的 `TargetResult`、`BaseInfo` 与命令行的 JSON 输出使用相同的字段，TXT 与 CSV 输出也包含最终地址和跨资产跳转。

## Cookie

一次扫描是一个独立的 Cookie 会话：入口请求、规则请求和图标请求共用，跳转链上一跳设置的 Cookie 会带到下一跳，扫描结束后释放。不同扫描之间、不同资产之间互不可见，引擎也不会随扫描目标数量累积 Cookie。

## 规则路径

规则的 `path` 以扫描目标的路径为前缀：目标 `http://a.com/app/` 加 `path: /admin` 请求 `/app/admin`。目标的查询串只属于目标页面本身（`path: /` 时保留），其他路径不携带；`#` 之后的片段不会发往服务端。
