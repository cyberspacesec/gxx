# 资产与跳转

本文说明扫描目标如何确定、扫描过程中哪些跳转会被跟随，以及结果里与跳转有关的字段。

## 扫描目标

一个扫描目标由**协议、主机、端口**共同确定，称为一个资产：

| 输入 | 资产 |
|---|---|
| `http://a.com` | `http://a.com:80` |
| `https://a.com` | `https://a.com:443`，与上一行是两个目标 |
| `http://a.com:8080` | 第三个目标 |

主机不区分大小写，省略的端口按协议补全，所以 `http://A.com:80/` 与 `http://a.com` 是同一个目标，批量扫描时只扫一次。

目标未写协议时由 GXX 确定：端口 80 只尝试 http，端口 443 只尝试 https，其余**先 https 后 http**。写成 `ip:端口` 时两种协议连接的是同一个端口，TCP 连接失败就不再换协议，不可达的目标只等待一次超时。

## 跳转链

入口请求逐跳跟随跳转，合计最多 5 跳，回到已访问过的地址时停止。

| 类型 | 是否跟随 |
|---|---|
| `http`：30x 的 `Location` | **总是跟随**，可以指向其他主机、协议或端口。`http://a.com` → `https://a.com`、`a.com` → `www.a.com`、控制台 → 统一登录页都会跟过去 |
| `refresh`：`Refresh` 响应头或 `<meta http-equiv="refresh">`（延迟不超过 10 秒且带有地址；`<noscript>` 中的不算） | 目标与当前页属于同一资产时跟随 |
| `javascript`：跳转壳里的脚本跳转，见下 | 目标与当前页属于同一资产时跟随 |

30x 是服务端明确给出的地址，所以无条件跟随。`refresh` 与 `javascript` 是从页面内容里**静态识别**出来的，可能认错，因此只在当前页所在的资产内跟随；指向其他资产时不访问，地址写入结果的 `redirect_to`。

链上的**每一页都是指纹素材**：

- 规则里的 `path: /`（跟随重定向的 GET）依次匹配链上各页，任一页满足即命中。入口的 302 响应本身（状态码、`Location`、`Set-Cookie`）和最终页面的内容都可以写规则。
- 一条指纹的多条规则要在**同一页**上成立；分别落在不同页面上的规则不会拼成一次命中。
- `follow_redirects: false` 的根路径规则只匹配第一页，并复用入口响应，不再另发请求。
- 其他路径的规则（如 `path: /admin`）以扫描目标为前缀单独请求，同样跟随 30x。

结果中的标题、技术栈、备案号、图标哈希和 `status_code` 取自链上最后一页，`final_url` 是它的地址。扫描 `http://a.com` 而它 301 到 `https://www.a.com/` 时，结果的 `url` 是 `http://a.com`，`final_url` 是 `https://www.a.com/`，识别到的指纹记在 `http://a.com` 这一条结果里。

### 发往其他主机的请求

跟随 30x 到其他主机，以及读取页面在 CDN 上声明的图标时，请求会离开扫描目标。这些请求只带通用请求头（`User-Agent`、`Accept`、`Accept-Language`、`Referer`）：`WithCustomHeaders` 设置的请求头、规则里手写的请求头都只发给扫描目标自身，令牌不会随跳转带给其他主机。

页面明确声明的图标（`<link rel="icon">` 等）可以位于其他主机，图标请求跟随重定向最多 5 跳。没有声明图标时猜测的候选（`og:image`、`<img>`、图片链接）只请求与页面同一资产的地址。30x 响应不提取图标。

### 脚本跳转的识别范围

GXX 不执行 JavaScript，只做静态识别，并且只识别写法明确的情况；识别不了就当作没有跳转。

页面必须是**跳转壳**：正文不超过 16 KiB，没有表单、输入控件和框架，可见文字不超过 512 字节。在这样的页面里查找：

- `location`、`location.href` 的赋值，以及 `location.replace()`、`location.assign()` 调用；`location` 可以挂在 `window`、`self`、`top`、`parent`、`document`、`globalThis` 上，其他对象的同名属性不算。
- 目标必须是字符串字面量。字面量后用 `+` 拼接时，只有字面量已经包含 `?` 才采用——路径是完整的，拼接的是时间戳一类的参数值，例如 `"/doc/page/login.asp?_" + (new Date()).getTime()`。
- 整个页面只出现**一个**不同的目标才跟随。按设备或语言分流的多目标写法无法静态判断，放弃。

字符串和注释里的"代码"、比较（`==`）、追加（`+=`）、`location.hash`、`window.open`、外链脚本、模板插值都不会被当成跳转。

识别到的地址如果与当前页不在同一资产，不访问，只写入 `redirect_to`。因此识别出错的最坏结果是多请求一次同一站点的另一个页面，而且跳转壳本身仍然参与匹配。

## 结果字段

| 字段 | 含义 |
|---|---|
| `url` | 带协议的扫描目标 |
| `final_url` | 跳转链最后一页的地址；没有跳转时与 `url` 相同 |
| `redirect_to` | 页面里识别出的、指向其他资产而没有跟随的跳转地址；没有则省略 |
| `redirects` | 跳转链，每一跳包含 `type`、`status`（发出跳转的响应的状态码）、`from`、`to`、`followed` |
| `status_code`、`title`、`tech_stack`、`icp`、`headers` | 描述 `final_url` 对应的页面 |

`followed` 为 `false` 的一跳就是 `redirect_to` 的来源。SDK 的 `TargetResult`、`BaseInfo` 与命令行的 JSON 输出使用相同的字段，TXT 与 CSV 输出也包含最终地址和未跟随的跳转。

## Cookie

一次扫描是一个独立的 Cookie 会话：入口请求、规则请求和图标请求共用，跳转链上一跳设置的 Cookie 按域名规则带到下一跳，扫描结束后释放。不同扫描之间互不可见，引擎也不会随扫描目标数量累积 Cookie。

## 规则路径

规则的 `path` 以扫描目标的路径为前缀：目标 `http://a.com/app/` 加 `path: /admin` 请求 `/app/admin`。目标的查询串只属于目标页面本身（`path: /` 时保留），其他路径不携带；`#` 之后的片段不会发往服务端。
