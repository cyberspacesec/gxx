# GXX 指纹规则格式说明

## 指纹文件结构

- **文件格式**: YAML
- **文件扩展名**: .yml
- **编码**: UTF-8

## 基本结构

```yaml
id: 指纹规则的唯一标识符

info:
  name: 指纹名称，描述识别的目标系统或组件
  author: 规则作者
  verified: false # 是否经过验证
  description: |
    详细描述指纹对应的系统或组件，
    支持多行文本
  reference:
    - 参考资料链接，可以是官网、CVE链接等
    - 支持多个参考链接
  tags: cve,web,apache,ssh # 标签，用逗号分隔，便于分类和检索
  created: 2025/04/01 # 创建日期，格式为YYYY/MM/DD

set:
  # 变量定义，用于后续规则中引用
  num: randomInt(800000000, 1000000000) # 生成800000000到1000000000之间的随机数
  payload: randomLowercase(20) # 生成20个随机小写字母
  hostname: request.url.host # 获取目标主机名
  host: request.url.domain # 获取目标域名

rules:
  # 规则定义，每个规则包含请求和匹配表达式
  r0: # 规则ID，通常以r0, r1, r2...命名
    request:
      type: http # 请求类型（http/tcp/udp），HTTP请求可省略
      method: GET # 请求方法，默认GET
      path: / # 请求路径，默认/
      headers: # 请求头，可选
        User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
        Content-Type: application/json
      body: '{"key": "value"}' # 请求体，POST请求时使用
       follow_redirects: true # 是否跟随重定向，默认true（程序端默认跟随）
    expression: response.status == 200 && response.body.bcontains(b"特征字符串") # 匹配规则表达式

  r1:
    request:
      method: GET
      path: /admin
    expression: response.status == 302 || response.headers["Server"].contains("Apache")

  r2:
    request:
      method: GET
      path: /{{num}}.php # 使用set中定义的变量
    expression: response.body.bcontains(b"404") || response.icon_hash == "1236214049"

# 最终判断表达式，组合多个规则的结果
expression: r0() && (r1() || r2())
```

## Info 字段详细说明

| 字段           | 描述                                          | 必填  | 示例                                  |
|---------------|----------------------------------------------|------|--------------------------------------|
| name          | 指纹名称，描述目标系统或组件                      | 是    | "Apache Tomcat"                     |
| author        | 规则作者                                       | 是    | "zhizhuo"                           |
| verified      | 是否经过验证                                    | 否    | true/false                          |
| description   | 详细描述指纹对应的系统或组件                      | 是    | "Apache Tomcat 应用服务器识别"        |
| reference     | 参考资料链接数组                                | 否    | ["https://tomcat.apache.org/"]      |
| tags          | 标签，用逗号分隔                                | 否    | "web,apache,tomcat"                 |
| created       | 规则创建日期                                   | 是    | "2025/04/01"                        |


## 请求类型说明

### HTTP 请求

```yaml
type: http              # 可省略
method: GET/POST/PUT/DELETE/...
path: 请求路径，如 /login
headers:                # 可选
  User-Agent: ...
body: 请求体
follow_redirects: true  # 是否跟随重定向，默认 true
```

### TCP 请求

```yaml
type: tcp
host: 目标主机，如 "{{hostname}}:80"
data: 发送的数据，如 "test\n"
data-type: text          # 可选：默认 text，"hex" 表示按十六进制解码 data
read-size: 4096          # 可选：读取字节数上限
read-timeout: 5          # 可选：单位秒
```

### UDP 请求

```yaml
type: udp
host: 目标主机，如 "{{hostname}}:53"
data: 发送的数据
data-type: text          # 同上
read-size: 1024
read-timeout: 5
```

### Raw HTTP 请求（精确控制原始报文）

```yaml
type: http
raw: |
  GET / HTTP/1.1
  Host: {{hostname}}
  User-Agent: gxx-fingerprint
  X-Custom: test
```

> `raw` 字段非空时优先走 `projectdiscovery/rawhttp`，可精确控制头部顺序、保留非常规字符，适合对协议格式敏感的指纹识别场景。

## 单条 Rule 的全部字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `request` | object | 上方四种请求模板之一 |
| `expression` | string | 单规则 CEL 表达式（必填）|
| `expressions` | []string | 多表达式数组（保留兼容） |
| `output` | map | 该规则匹配后向 varMap 注入的变量，用于后续规则引用（CEL 表达式形式）|
| `stop_if_match` | bool | 命中后立即停止后续 rule 评估 |
| `stop_if_mismatch` | bool | 未命中立即停止 |
| `before_sleep` | int | 发起请求前 sleep 秒数（应对部分依赖时序的接口） |

示例 — 用 `output` + `submatch` 提取版本号供后续规则使用：

```yaml
rules:
  r0:
    request:
      method: GET
      path: /
    expression: response.raw_header.ibcontains(b"Server: nginx")
    output:
      ver: submatch("nginx/(?<v>[\\d.]+)", string(response.raw_header))["v"]
  r1:
    request:
      method: GET
      path: /admin
    expression: response.status == 200 && r0()  # r0 命中后 ver 才可用
expression: r0() && r1()
```

## 请求 / 响应对象属性

> 类型定义来自 `utils/proto/http.proto`（编译产物 `utils/proto/http.pb.go`），CEL 表达式中可直接通过字段名访问。

### request（proto.Request）

| 字段 | 类型 | 说明 |
|------|------|------|
| `request.url` | `UrlType` | URL 拆解结构，见下文 |
| `request.method` | string | HTTP 方法（如 `GET`） |
| `request.headers` | `map[string]string` | 请求头，key 一律小写；用 `in` 判断键存在 |
| `request.content_type` | string | `request.headers["content-type"]` 的快捷字段 |
| `request.body` | bytes | 请求体（GET 时为空） |
| `request.raw` | bytes | 原始请求报文 |
| `request.raw_header` | bytes | 原始请求头 |

### response（proto.Response，HTTP）

| 字段 | 类型 | 说明 |
|------|------|------|
| `response.status` | int32 | HTTP 状态码 |
| `response.url` | `UrlType` | 实际响应 URL（可能经重定向） |
| `response.headers` | `map[string]string` | 响应头（同 request.headers） |
| `response.content_type` | string | `Content-Type` 快捷字段 |
| `response.body` | bytes | 响应体 |
| `response.raw` | bytes | 原始响应（含头 + body） |
| `response.raw_header` | bytes | 原始响应头 |
| `response.icon_hash` | string | favicon mmh3 哈希（扫描入口页，或根路径 GET 的 HTML 响应） |
| `response.latency` | int64 | 响应延迟，单位毫秒（可用于异常分析） |

### UrlType（`request.url` / `response.url`）

| 字段 | 示例 |
|------|------|
| `scheme` | `"http"` / `"https"` |
| `domain` | `"example.com"` |
| `host` | `"example.com:8080"` |
| `port` | `"8080"`（注意是字符串） |
| `path` | `"/a/b"` |
| `query` | `"k=v&x=y"` |
| `fragment` | 锚点 |

### TCP/UDP / Raw 响应

- `response.raw` — 原始响应字节流（其他 HTTP 字段为零值）

## 表达式语法

### 匹配响应状态
```
response.status == 200
```

### 匹配响应体
```
response.body.bcontains(b"特征字符串")  # 二进制包含，区分大小写
response.body.contains("特征字符串")    # 字符串包含，区分大小写
response.body.ibcontains(b"特征字符串") # 二进制包含，不区分大小写（推荐）
```

### 匹配响应头
```
response.headers["Server"] == "Apache"
response.headers["Content-Type"].contains("json")
response.raw_header.bcontains(b"Server: Apache") # 使用原始响应头进行二进制匹配
response.raw_header.ibcontains(b"server: apache") # 使用原始响应头进行不区分大小写的二进制匹配
```

### 匹配图标哈希
```
response.icon_hash == "哈希值" # 入口页或根路径 GET 的 HTML 响应
```

### 匹配原始响应
```
response.raw.bcontains(b"特征字符串") # 二进制包含，区分大小写
response.raw.ibcontains(b"特征字符串") # 二进制包含，不区分大小写
```

### 正则表达式匹配
```
response.body.bmatches(b"正则表达式")
response.raw_header.bmatches(b"正则表达式")
```

### 组合表达式
```
条件1 && 条件2 # 与
条件1 || 条件2 # 或
!条件 # 非
```

## 辅助函数

> 以下是 GXX 当前 CEL 引擎实际暴露的所有函数（来自 `pkg/cel/celprogram.go`）。
> 文档外的函数（如 `sha1` / `sha256` / `randomAlpha` / `randomNumber` / `randomUppercase`）在 GXX 中**不存在**，请勿在规则中使用。

### 随机数 / 随机字符串

- `randomInt(min, max)` — `[min, max)` 范围内随机整数
- `randomLowercase(length)` — 指定长度的随机小写字母字符串

### 编码 / 哈希

- `base64(s)` / `base64(b)` — Base64 编码（接受 string / bytes）
- `base64Decode(s)` / `base64Decode(b)` — Base64 解码
- `md5(s)` — 32 位十六进制 MD5 字符串
- `hexdecode(s)` — 十六进制串解码为字符串
- `faviconHash(s)` / `faviconHash(b)` — favicon 内容的 mmh3 哈希（int64）

### URL 处理

- `urlencode(s)` / `urlencode(b)` — URL 编码（`url.QueryEscape`）
- `urldecode(s)` / `urldecode(b)` — URL 解码（`url.QueryUnescape`）

### 字符串处理

- `icontains(s, sub)` (string member) — 不区分大小写包含
- `substr(s, start, length)` — 截取 `[start, start+length)` 子串
- `replaceAll(s, old, new)` — 全部替换
- `printable(s)` — 仅保留可打印字符
- `toUintString(s, direction)` — 规范化数字字符串，`direction == "<"` 表示先反转

### 字节匹配

- `bcontains(b)` (bytes member) — 字节包含，区分大小写
- `ibcontains(b)` (bytes member) — 字节包含，不区分大小写（**推荐**）
- `bstartsWith(b)` (bytes member) — 字节前缀

### 正则

- `bmatches(pattern, b)` (string member) — 字节流正则匹配，返回 bool
- `submatch(pattern, s)` (string member) — 命名捕获字符串，返回 `map[string]string`
- `bsubmatch(pattern, b)` (string member) — 命名捕获字节流，返回 `map[string]string`

> 正则引擎是 `dlclark/regexp2`（兼容 .NET 风格），支持 `(?<name>...)` 命名捕获、零宽断言、回溯引用等。

### 时间（无参占位 `0`）

- `year(0)` — 当前年份 4 位（如 `"2026"`）
- `shortyear(0)` — 当前年份 2 位
- `month(0)` — 当前月份 2 位
- `day(0)` — 当前日期 2 位
- `timestamp_second(0)` — 当前 Unix 时间戳（秒，字符串）

### 杂项

- `sleep(seconds)` — 阻塞指定秒数（CEL 上下文中谨慎使用）

### 用 submatch 提取版本号（指纹细分）

```yaml
id: nginx-fingerprint

info:
  name: Nginx
  author: 作者名
  description: 识别 Nginx 并按版本号细分
  created: 2026/05/22

rules:
  r0:
    request:
      method: GET
      path: /
    expression: response.raw_header.ibcontains(b"Server: nginx")
    output:
      ver: submatch("nginx/(?<v>[\\d.]+)", string(response.raw_header))["v"]
  r1:
    request:
      method: GET
      path: /
    # ver 由 r0 的 output 注入，CEL 表达式可直接引用，便于按主版本号细分指纹
    expression: r0() && ver.startsWith("1.")

expression: r1()
```

## payloads 多组载荷

`payloads` 顶层字段用于在同一指纹下并行尝试多组变量（如多套常见路径、多个登录页特征），每组都会与下面的 `rules` 组合执行：

```yaml
payloads:
  continue: true       # true=命中后继续尝试下一组；false=命中即停
  payloads:
    set1:
      path: "/admin/login"
      keyword: "管理后台登录"
    set2:
      path: "/manage/login.html"
      keyword: "后台管理系统"

rules:
  r0:
    request:
      method: GET
      path: "{{path}}"
    expression: response.status == 200 && response.body.ibcontains(bytes(keyword))

expression: r0()
```

> 每个 set 块中的键会写回到 varMap，可用 `{{}}` 模板替换，也可在 CEL 中直接引用。
> 典型场景：同一 CMS 在不同部署下后台路径不同，可通过多组 path + 关键字共同提高识别覆盖率。

## 常见陷阱

1. **大小写敏感**：`response.headers` 的 key 在解析时统一转为**小写**；写 `response.headers["Server"]` 取不到值，应写 `response.headers["server"]`，或改用 `response.raw_header.ibcontains(...)`。
2. **`raw_header` 是 bytes**：必须搭配字节方法（`bcontains` / `ibcontains` / `bmatches`），不能用字符串方法。
3. **`response.body` 是 bytes**：同上。混用会触发 CEL 类型错误。
4. **不要在指纹中使用 `sleep(N)`**：会阻塞规则池 worker，影响整体扫描吞吐。
5. **不存在的函数**：`sha1` / `sha256` / `randomAlpha` / `randomUppercase` / `randomNumber` 等在 GXX 中**未实现**。请使用本文 §辅助函数 列出的真实函数。

## 最佳实践

- **规则命名**: 使用有意义的ID和名称，反映目标应用或服务
- **变量引用**: 使用 `{{变量名}}` 语法引用set中定义的变量
- **规则组合**: 使用逻辑操作符 `&&`（与）和 `||`（或）组合多个规则
- **文档完善**: 提供详细的描述和参考链接，便于他人理解和维护
- **测试规则**: 在提交前充分测试规则的有效性和准确性
- **规则分类**: 使用适当的标签对规则进行分类，便于检索
- **优先 ibcontains**: 字节匹配优先 `ibcontains`，规避大小写差异
- **`response.icon_hash` 使用范围**: 扫描入口页支持非根路径、重定向和 XHTML；其他规则响应仅在根路径 GET 的 HTML 场景抓取。范围与限制见 [网站元数据识别](网站元数据识别.md)

## 使用 raw_header 和 ibcontains 的示例

### 根据HTTP响应头识别服务器

```yaml
id: server-identification

info:
  name: 服务器识别
  author: 作者名
  description: 根据HTTP头识别特定服务器
  created: 2025/04/07

rules:
  r0:
    request:
      method: GET
      path: /
    expression: response.raw_header.ibcontains(b"Server: Apache")

  r1:
    request:
      method: GET
      path: /
    expression: response.raw_header.ibcontains(b"X-Powered-By: PHP")

  r2:
    request:
      method: GET
      path: /
    expression: response.headers.ibcontains(b"nginx")

expression: r0() || r1() || r2()
```

该示例使用 `response.raw_header.ibcontains()` 函数来不区分大小写地匹配HTTP响应头，用于识别不同类型的Web服务器。
