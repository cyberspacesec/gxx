# GXX 指纹数据与验证

GXX 的规则目录与扫描结果分别表达规则来源、产品信息、提取结果和测试状态。调用方通过 `RuleCatalog` 导入完整规则目录，通过 `TargetResult.Matches` 保存原始命中，通过 `TargetResult.Products` 展示归并后的产品。公共字段和使用示例见 [SDK 使用文档](../sdk/sdk.md)。

## 数据约定

| 信息 | SDK 字段 | 语义 |
|---|---|---|
| 规则作者 | `Info.Author` | YAML 作者，不作为厂商 |
| 产品厂商 | `Info.Vendor`、`Info.Product.Vendor` | 产品目录核实的厂商；未知时为空 |
| 来源验证声明 | `Info.Verified`、`Info.VerificationStatus` | 区分来源已验证、未验证与未声明 |
| 样本记录 | `Info.Validation` | 测试方法、样本数、复核日期与适用范围 |
| 置信度 | `Info.Confidence` | 经外部数据校准的值；未知时为 JSON `null` |
| 规则来源 | `Info.Source` | 文件路径、实际字节 SHA256 与规则包源版本 |
| 产品版本 | `ProductVersion`、`ProductVersions` | 成功子规则的 `output.product_version`；冲突时不返回单一确定版本 |
| 检测证据 | `MatchedRules[].Evidence` | 实际执行分支的表达式、字段、片段与字节位置 |
| 产品目录 | `Info.Product`、`ProductCatalog()` | 稳定目录 ID、规范名称、别名、分类、标签、参考资料及有依据的 CPE |
| 质量缺项 | `RuleCatalog()[].MissingMetadata` | 尚需核实的数据项，不代表规则失效 |

产品 ID 由目录显式定义，不按规则作者、拼音或 HTTP 传输协议猜测产品。CPE 只表示产品映射，不代表发现 CVE 或漏洞。创建时间、来源验证声明与当前样本复核日期分别保存。规则版本与产品版本不能混用。

ARL 的 `web-arl` 与 `web-资产灯塔系统` 保留两条原始规则和来源记录，产品目录将其归并为 `arl.arl`。版本冲突时保留全部有限版本候选并标记 `VersionConflict`。未映射的产品按规则分别展示，ID 留空，不合并同名猜测结果。

2026-10-01，内置目录共 **2,349 条 YAML**。以下数字来自 SDK `RuleCatalog`，包含 YAML 信息和独立产品目录的有效信息：

| 有明确产品映射的规则 | 70 |

| 来源声明已验证 | 143 |

| 来源未声明验证状态 | 1 |
| 有专项样本记录的规则 | 8 |

其余产品、厂商、参考资料及专项测试记录仍属于待核实数据。目录接口对全部规则提供相同结构和缺项说明，不能把完整接口覆盖解释为全部产品元数据已经核实。通用描述和来源未验证也不能直接解释为规则无效。

产品目录优先引用官方产品主页、官方文档和维护仓库；没有可追溯依据时保留空值。空引用与 `example.com` 占位链接不作为产品依据。目录中的 Apache HTTP Server、WordPress 和 Fastjson CPE 对照 [NVD CPE 字典](https://nvd.nist.gov/products/cpe) 的产品记录；不自动生成其他产品的 CPE。每个产品的直接资料链接保存在 `ProductInfo.References`。

## 样本与回归测试

`sdk/product_integration_test.go` 使用本机可控 HTTP 服务，逐样本执行全部 2,349 条规则。37 个样本共完成 **86,913 个规则任务、518 次 HTTP 请求**，任务失败为 0。专项记录绑定实际规则 SHA256；文件内容变化后旧记录不再适用。

| 产品 | 阳性样本 | 阴性样本 | 核对内容 |
|---|---:|---:|---|
| Fastjson 1 | 4 | 8 | 明确 Java 包特征、JAR 版本；排除通用 JavaScript、其他 JSON 解析器与 Fastjson 2 |
| WordPress | 4 | 1 | generator 版本、大小写、静态资源与版本缺失；排除 Drupal 版本串用 |
| Apache HTTP Server | 2 | 1 | Server 产品及版本；版本隐藏时仍识别 |
| Apache Tomcat | 3 | 1 | 标题、错误页；不把 Coyote 协议版本当作 Tomcat 版本 |
| Jenkins | 2 | 2 | 专有响应头与代理协议；排除普通版本文本 |
| nginx | 3 | 2 | Server 产品边界、大小写、隐藏版本；排除 nginx-webui |
| ARL 两条来源规则 | 2 | 2 | 两条原始命中与同一产品归并 |

`sample-tested` 只表示上述有限合成样本通过，不表示真实部署的准确率或召回率，置信度保持未知。Fastjson 使用类名特征，普通 `JSON.parse` 和通用 `unclosed string` 不再构成产品识别依据；Jenkins 使用实际存在的专有响应头，避免把 `*` 当作包含匹配的通配符。

其他回归覆盖：全部 6,036 个 CEL 表达式编译；证据开关下的完整命中和产品版本一致；AND、OR、NOT 实际分支及短路；Unicode 字节位置、二进制片段与正文末尾命中；提取失败、失败子规则、版本冲突与结果预算；并发实例、输入副本、返回值副本、规则重载和摘要失效；图标哈希、完整图标读取、标题与 ICP 提取。完整样本测试不替代逐产品真实部署测试。

GOTOOLCHAIN=go1.25.0 go test -count=1 ./...

## 资源与性能

匹配证据使用固定追踪区，只记录实际布尔结果，不重放 CEL、请求、等待或随机函数。执行计划保存字段和定位条件，不保留完整 AST。定位在成功分支上进行，片段复制为独立有界数据，SDK 结果不持有完整正文。每条子规则最多 16 个证据、每个片段最多 256 个原始字节，每次表达式最多 128 个布尔节点，每条指纹最多 64 个成功子规则，超出时提供截断标记。

正文读取上限为 512 KiB，图标哈希采用完整流读取。图标哈希算法、编码行宽、补齐和换行语义保持一致。正则字符缓冲与响应归一化共用单目标 8 MiB 的估算缓存预算；执行状态、请求配置、缓存作用域及目录覆盖独立属于 Engine。只读编译程序可以共享，调用方输入和返回的可变数据不跨实例共享。

2026-10-01，macOS / Apple M2 / Go 1.25.0，依赖版本不变。基线为 `5f42188` 的 2,348 条规则，当前为 2,349 条规则；本机固定 Apache / WordPress 响应，默认 200 规则协程和 5 目标并发，每个进程预热一次后扫描 50 个目标，基线与当前交替测量三组。以下为三组中位数；累计分配包含同进程 HTTP 靶场，峰值 RSS 包含启动和规则加载，不等于长期存活堆或 IDE 内存：

| 指标 | 小响应基线 | 小响应当前 | 256 KiB 响应基线 | 256 KiB 响应当前 |
|---|---:|---:|---:|---:|
| 50 目标 HTTP 请求数 | 750 | 700 | 750 | 700 |
| 规则任务数 | 117,400 | 117,450 | 117,400 | 117,450 |
| 50 目标总耗时（ms） | 154.07 | 187.20 | 743.60 | 814.24 |
| 累计分配量（MiB） | 47.20 | 38.83 | 449.71 | 462.42 |
| 分配对象数 | 1,248,195 | 1,064,892 | 1,360,311 | 1,166,801 |
| 预热并 GC 后存活堆（MiB） | 18.95 | 21.56 | 22.51 | 26.00 |
| 扫描后 GC 存活堆（MiB） | 20.45 | 22.84 | 24.36 | 26.69 |
| 进程峰值 RSS（MiB） | 76.44 | 80.83 | 126.33 | 132.70 |

50 目标请求缓存统计扣除预热后：当前命中 183,600 次、未命中 500 次，命中率 99.7284%；基线命中 183,700 次、未命中 550 次，命中率 99.7015%。命中统计不是网络请求计数，图标和基础探测等请求由靶场独立计数。扫描结束后缓存条目和跟踪 URL 均为 0。

单目标 `BenchmarkFullFingerprints` 的三组测量中，小响应累计分配中位数约 0.71 MiB，分配对象约 21,154；256 KiB 响应约 12.80 MiB、21,874 个对象。基准的 HTTP 服务与并发目标测试不同，不能混用两组绝对值。复核命令：

```bash
GOTOOLCHAIN=go1.25.0 go test ./sdk -run '^$' -bench '^BenchmarkFullFingerprints$' -benchmem -benchtime=1s -count=3
```

默认详情回传包含产品信息和证据执行计划，有固定常驻成本。测量中的小响应累计分配与请求数下降，但并发耗时、常驻堆和部分大响应分配增加，不能宣称所有指标都下降或已经达到性能极限。无需证据详情的调用方可使用 `WithMatchDetails(false)`，产品版本、元数据和命中结果仍回传；消费大量目标时使用 `ScanCallback` 或 `ScanIterator`，避免一次保留全部结果。

## 目录维护

产品目录以 `sdk/catalog.json` 保存，YAML 只承载原有识别字段与提取表达式。扩展目录使用 `WithProductCatalog`，以明确的 `RuleIDs` 关联产品，按产品 ID 一致覆盖元数据。专项记录使用 `WithRuleAssessments`，包含规则 ID、SHA256、方法、样本数及范围；只有摘要一致时应用。来源版本通过 `WithRuleSourceVersion` 声明，不能覆盖原生内置来源的实际版本。

修改检测条件或输出表达式后，先检查普通页面、相似产品和缺失版本的阴性样本，再检查阳性响应，并重算规则摘要。`.gitattributes` 对 YAML 禁用 Git 自动换行转换，使跨平台 SHA256 一致。产品参考资料变化应复核实际链接，未知信息不能用作者、占位链接或默认置信度补齐。
